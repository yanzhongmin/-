# 光位 · 需求确认单

> 由 10 个问答锁定（2026-11-17）。改动请直接说。

## 一句话

一个手机网页 App：拍照**前**告诉你人站哪儿、摆什么姿势、参数怎么设；按快门用 App 自己拍，"一键套用"把推荐的调色与氛围直接烧进出片；拍完**再**按预设调美颜和氛围感，直接保存。照片不上传。

## 用户

- 单人使用，**摄影师视角**：他举着手机，被拍的人（女朋友 / 家人 / 朋友）在画外等着。
- 手机：华为 P60，浏览器（Chromium 内核）。
- 要**随时随地**能用 → 部署到 GitHub Pages（公网 https）。

## 主流程

### 1. 实时取景
叠三分线 + 虚线目标框 + 真人大小剪影。一行建议：人占画面几成高、手机放多高、退到几米外。

### 2. 人物设定（每次快速选，不建档案）
对象（女朋友 / 家人 / 朋友 / 自己）+ 今天衣服主色 + 身高区间。
→ 影响：剪影造型（裙/裤、长发）、框的大小、优先选与衣服颜色反差大的背景。

### 3. 姿势
20 个姿势，横滑选。选中的剪影**以真人大小半透明画在目标框位置上**。
配一句给摄影师看的人话指令（"身体朝左 45°，头转回来，一只手插腰"）。
> 明确：建议只给摄影师看，不需要"举给对方看"的大字模式，也不需要语音。

### 4. 氛围感
按当前这一帧算：光线方向（逆光 / 侧光 / 顶光）、地平线位置、竖线穿头、背景杂乱度、虚实前景建议、具体动作情绪。

### 5. 参数（10 项，每项带"为什么"）
ISO / 快门 / EV / 白平衡 / 镜头焦段 / 机位高度 / 拍摄距离 / 人占画面比例 / 光位 / 对焦点。
「一键套用」→ 在 App 内直接套到出片上（调色 + 氛围 + 裁切），所见即所得；同一组参数另有「复制参数」，想用系统相机拍就照抄。
> 硬件级写入（曝光补偿 / 白平衡 / 变焦）不做：各机型 `applyConstraints` 支持不一致、单位还不统一（有的按 0.1EV），盲设可能拍出全黑。手机相机的自动曝光在大多数打卡场景够用，"好不好看"由调色负责。

### 6. 对位引导（关键）
人走进画面后，实时给方向提示：「往左半步」「再退一点」「够了别动」。
- 左右 + 前后都要。
- 用背景差分找"新出现的高瘦区域"，**认不准就闭嘴**，宁可不说不瞎指挥。

### 7. 快门 → 出片
白闪，套上参数与调色，输出 3:4 竖版 1440×1920（4:5 / 1:1 / 9:16 暂未做，见"待办"）。

### 8. 拍完再调（拍后编辑）
- 美颜：磨皮（保睫毛发丝）、提亮肤色、去油光、气色、肤色统一、轻微拉长腿（自动少量）、瘦脸**滑杆默认 0**。
- 氛围：8 个调色预设（清透 / 胶片 / 电影 / 港风 / 夜景 / 黑白 …）+ 强度滑杆。
- 预览即最终效果，所见即所得；保存到手机。

## 技术决定

| 项 | 决定 | 理由 |
|---|---|---|
| 形态 | 纯静态网页（免构建，PWA 可加到主屏幕） | 环境只能产出网页；免构建部署最省事 |
| 相机 | `getUserMedia` 取景，只读画面做分析；不写硬件参数 | 各机型对曝光/白平衡的支持和单位不统一，写坏了会拍出全黑 |
| 姿势图 | 参数化人形剪影（关节 FK） | 不依赖付费生图 API，离线即时 |
| 场景分析 | 本地像素统计（亮度/色温/地平线/竖线/纹理/肤色） | 不上传，几十毫秒一帧 |
| 调色 | CSS filter + 混合图层（预览）/ canvas（出片） | 预览与成片一致 |
| 美颜 | 肤色遮罩 + 保边模糊 | 无 ML 依赖，效果稳定可预期 |
| 瘦脸大眼 | 手动滑杆，默认 0，定位失败则隐藏 | 网页内人脸识别不可靠 |

## 明确不做

- 人脸关键点级的美型（大眼 / 推鼻 / 改下颌线）默认不自动执行。
- 语音播报、给对方看的大字姿势卡。
- 上传云端、账号、社交分享后台。

## 待办 / 已知局限

- **画幅切换**（4:5 / 1:1 / 9:16）未做，目前固定 3:4。
- **人脸关键点级美型**（大眼 / 推鼻 / 改下颌线）只做到椭圆瘦脸，且默认 0。
- **肤色定位在夕阳、沙滩这类暖色大环境下会误判**——此时"往左/右挪"提示会自动闭嘴（已有可信度闸门），但不会给出替代指引。
- **部署**：GitHub Pages 需要一个仓库 + Token，等用户给。
